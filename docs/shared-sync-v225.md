# 共有抽選の同期修正 v225

更新日: 2026-11-16  
クライアント版: `20261116-v225-stable-server-sync`

## 目的

Windows側の既存3D抽選機で決まった結果をサーバーからクライアントへ配信し、ゲーム別のBET・WINをサーバーへ返し、ペイアウト設定を次の盤面に反映する。この周期が通信エラーや再接続で停止しないよう、通信とラウンド終了処理を修正する。

## 確認した原因と修正

- HTTP状態取得が返すsnapshotを次のHTTP取得の契機にしており、リクエストが連鎖していた。状態取得を単一の処理へまとめ、通常800ms間隔、同時取得の共有、429時のRetry-Afterと段階的な待機を導入。
- 同じIPの全HTTP要求を制限していたため、APIの過剰呼び出しでHTML・JavaScript・画像も429になった。静的ファイルをAPI制限から分離。ローカルのCloudflare Tunnel経由はCF-Connecting-IPを使って訪問者ごとにAPI上限を適用。直接接続の任意転送ヘッダーは信頼しない。
- WS接続後のHTTPエラーが正常なWSまで閉じていた。状態取得とホスト登録だけを再試行する。初期接続が3回失敗した場合も自動再試行を継続。
- ホストとプレイヤーが同じブラウザ保存キーを使っていた。ホスト専用セッションを分離し、登録成功を独立したフラグで管理。RTC通知でホスト登録済みと誤認しない。
- 新しいWS通知の後に届く古いHTTP応答で、ラウンド・段階・球数が巻き戻る問題を修正。ホストの入賞送信も、拒否された古い応答を使わない。
- 現在参加中のラウンドで取り逃した球は、同じラウンドのサーバーsnapshotから補完。前のラウンドの非同期配送を新しいラウンドへ混入させない。
- 正常精算の所有者をクライアント制御処理に一本化。ACK前に正常WINを破棄しない。ゲーム別BET・WIN・適用POを確定時に保存し、再読み込み後も同じ内容で再送。自分の精算ACKや古いwalletで次の盤面をリセットしない。
- サーバーから対象ラウンド不存在などの永久エラーが返った精算は、内容とエラーを別の保存領域に残し、画面で通知して次BETを妨げない。正常に精算済みとしては扱わない。
- 8球のサーバー結果を受信後も、盤面の処理状態が60秒以上まったく進まない場合は、既存の中断時0WINルールで終了し次ゲームへ復帰。結果が確定した正常精算や進行中の処理は対象外。
- 映像の接続開始を視聴者ごとに一本化。古い接続の非同期終了で新しい接続を閉じない。中継映像の途中参加・再接続は先頭のWebMデータから開始し、欠落したデータを検出して再取得。通常のラウンド切替では映像接続を作り直さない。
- 同じホストの新しいWSが生きている場合、古いWSの終了をホスト切断として通知しない。

## 更新手順（Windowsサーバー）

GitHub Pagesへの反映だけでは、Windows上のNode.jsサーバーは更新されない。

1. 実行中のサーバーランチャーを停止する。複数のサーバーを同じポートで起動しない。
2. 現在利用中のプロジェクトフォルダーをバックアップしてから、mainの更新を取り込む。Gitで管理している場合はそのフォルダーで `git pull --ff-only`。ZIPで導入した場合は [mainのZIP](https://github.com/naokingu123-cloud/cookie-link/archive/refs/heads/main.zip) を展開し、中身を既存フォルダーへ上書きコピーする。
3. 既存の `.runtime`、`.tools`、`data` は削除しない。特に `.runtime` のTunnel設定と保存データを維持する。Named Tunnelの再設定は不要。
4. 既存の `start-shared-machine-tunnel.cmd` から起動する。
5. ホスト監視画面とクライアントを再読み込みする。Windows Chrome/EdgeではCtrl+F5。公開版の [app-version.json](https://naokingu123-cloud.github.io/cookie-link/app-version.json) が上記v225であることを確認する。
6. ホストONLINE、8球配信、クライアント結果、次BETへ進むことを確認する。接続途中のラウンドは既存仕様に従って見送り、安定した接続で次ラウンドへ参加する。

## 検証

`npm run check` はJavaScriptの構文確認。`npm run test:shared` は既存の回帰に加え、以下のv225試験を実行する。

| 試験 | 対象 |
| --- | --- |
| `shared-client-http-backoff.mjs` | HTTP自己連鎖、間隔制御、同時取得、再接続、精算と次ラウンド |
| `shared-v225-host-recovery.mjs` | 起動再試行、ホスト登録、古い応答拒否、現在ラウンドの物理入賞報告 |
| `shared-v225-video-reconnect.mjs` | 映像接続の競合、途中参加、WebM先頭・欠落処理 |
| `shared-v225-payout-lifecycle.mjs` | 正常ACK、古いwallet、古いcheckpoint破棄、保存済み精算の再送 |
| `server-rate-limit-v225.mjs` | 実server.mjsの静的ファイル300要求、API429、待機後復帰、訪問者の分離 |
| `shared-v225-end-to-end.mjs` | 実server.mjsと配当middlewareで2クライアント・3ラウンド・4回目BET、切断・再接続、8球、精算重複、POフィードバック、ホストWS入替 |

サーバー試験は専用の一時データを使用する。統合試験の入賞番号とクライアントWINは試験用に入力するため、実3D物理やゲーム別配当計算の視覚検証を代替しない。

今回の検証用クラウドブラウザはWebGLが無効で、実3D抽選機の描画・実映像のなめらかさは確認できなかった。これは検証環境の制約であり、利用者のWindows描画障害を示すものではない。Windowsサーバーへのファイル反映・再起動と実機での連続プレイは別途必要。
