# v229: BET操作時のCREDIT反映・抽選機映像・20秒BET TIME

更新日: 2026-11-16  
版: `20261116-v229-immediate-bet-video`

## BETした時点でCREDITを減らす

各ゲームのBET加算ボタンを押した時点で、増額分をCREDITと表示CREDITから即座に予約する。送信前の選択変更は続けられ、減額した場合は予約済みの分だけ返却する。初期表示されている選択額を減らすだけで、まだ支払っていないCREDITを増やすことはしない。

中央の「BETする」は定期的な状態取得を待たずに登録を送信する。手動BET・AUTO REBETの登録開始時には、選択合計のうち未予約の残額だけを控除する。サーバーの成功応答やゲーム開始時には再控除しない。初期100万・通常27,000 BET・AUTO REBET初期ON・終了時のWIN加算はv228を維持する。

通信再送では同じ予約を使い、明示的に拒否された予約は返却する。送信結果が不明な場合は参加情報と財布で確認する。サーバーの残高情報を復元するときも、まだサーバーに登録していないローカル予約分を保つ。前ゲームの遅れた精算応答が新しいBETの控除を消すことを防ぐ。

残高不足の増額・BETは無効化する。全額BETは可能で、受付後は0になる。マイナス残高は許さず、再読み込みによる初期100万への再補充も行わない。

## 映像が表示されなかった原因

元の抽選機の `.a8-stage` は、絶対配置とinsetで親領域を満たす構造だった。クライアント用の動画CSSがこれを高さ未指定の相対配置に変更していたため、中身が絶対配置の動画・読み込み表示だけだと領域の高さが0になった。

公開v228のブラウザDOMで、外枠438.75×285.675pxに対してstageと2枚のvideoの高さが0pxであることを実測した。v229は元の絶対配置を維持し、ローカル3Dの初期化が完了していなくても映像領域を確保する。

さらに、`playing`・`timeupdate`を受け取るだけで映像が正常と判断していた処理を変更した。現在の接続に属し、映像寸法が0より大きく、実際の動画データが読み出せる状態だけを表示対象にする。古い接続から遅れて届くイベントを無視し、空のvideoを最後のフレームとして再表示しない。

WebMデータが届き続けても5秒間デコードできない場合は、先頭データからストリームを再取得する。ブラウザが自動再生を止めた場合には「映像を再生」、接続待ちには再試行ボタンを表示する。映像の再接続はボール情報の受信やゲーム進行を止めず、クライアント独自の抽選も開始しない。

同じプレイヤーIDを使う別の画面にも、画面ごとの識別子で映像を送れるようにした。ホスト自身への送り返しは除外する。通常のホスト用・プレイヤー用セッション分離は維持する。

## BET TIMEを20秒へ

`server-core.mjs`の既定値は20秒だったが、起動入口の`server.mjs`が10秒で上書きしていた。入口の既定値を20,000msへ変更した。クライアントはサーバーが配信する締切時刻を表示する。

BET期間の環境変数を指定せず隔離した実サーバーを起動し、health応答の`betDurationMs`と、実ラウンドの`betClosesAt - betOpenedAt`がともに20,000msになることを確認した。短い期間を明示する既存テスト用設定は引き続き利用できる。

## 検証

`npm run check`と`npm run test:shared`で既存の同期・財布・精算・物理抽選の回帰を確認する。追加の回帰は次の2本で、`test:sync`とShared machine checkにも含める。

- `tests/shared-v229-immediate-bet.mjs`: 実ゲームコードで、各枠・中央BETの即時控除、重複応答、拒否、未送信予約の返却、遅れて届いた精算と新規予約の重なりを確認する。
- `tests/shared-v229-video-display.mjs`: 表示領域の配置、未デコード映像の拒否、古いイベントの拒否、デコード停止時の再取得、再生操作、同じプレイヤーの別画面への配信を確認する。

ブラウザでの寸法測定と、接続・残高のVMテストを区別する。利用者のWindowsで更新が適用されたことや、利用者の回線上の映像が再生されたことまで、検証環境の成功だけで保証しない。

## 適用

Windows側のプロジェクトを最新mainへ更新し、既存の`start-shared-machine-tunnel.cmd`からサーバーを再起動する。今回はBET時間をサーバー側で変更するため再起動が必要。`.runtime`・`.tools`・`data`は保持する。

ホスト画面とプレイヤー画面も再読み込みする。公開クライアントの版は`20261116-v229-immediate-bet-video`。クライアントだけの更新をWindowsサーバーの更新完了とは扱わない。
