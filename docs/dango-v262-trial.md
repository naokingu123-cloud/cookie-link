# ダンゴデビンゴ v262：50〜150% 校正の試験実装

> 以下は配当変更の了承前の検討記録。2026年11月19日の「配当はかえてもいいので実装して」により配当案を採用し、AUTOで2,000倍役に到達できる第3型も追加した。現行仕様・公開版は [dango-v262.md](dango-v262.md) を参照する。以下の「保留」「選択が必要」は当時の状態であり、現在の作業を止める指示ではない。

## 状態と判断

この変更は `feature/v262-dango-calibration` の試験版。公開中の main / Pages への反映は保留する。

依頼された新盤面、FREE範囲拡張、FREE重なりと後半HITによるODDSを実装し、指定配当でP/O 50〜150%へ調整できるか調べた。**指定配当を維持したままでは50%へ届かず、「少し」の配当修正でも不足する。** 試験版は実際の変更幅を確認できるよう、基礎2,000倍を維持した調整案を動くコードにしている。

最終段の基礎配当は、追加の指示に従い20,000倍から2,000倍へ下げた。以下の全配置下限は20,000倍時点の証明であり、2,000倍版の全配置検証も別途実行中。前回の最小盤面ではこの役の期待値への寄与がゼロなので、その盤面の約298.55%という値は2,000倍への変更だけでは下がらない。

新ルールの全3,276通りの初期FREE配置と、それぞれ全2,300通りの拡張番号配置、合計7,534,800通りを調べた結果は次のとおり。8/25一様非復元抽選を前提とする。

|配置方法|指定配当を維持した場合の最小理論P/O|
|---|---:|
|配置可能な中心から一様ランダム|131.272001015241%|
|後半3球を見る前に期待値が最大の中心を選択|298.545169907642%|

これは前回の約104.58%とは条件が異なる。今回はFREE重なりと後半HITによるODDS、既存FREE上を中心にできること、最適な手動配置を含める。全盤面の最小値が約298.55%なので、初期盤面の出現率だけを混合しても50%にはならない。すべての配当を元の16.7478844%より多く残すなら、最適配置の期待値は50%を超える。従って50%には**少なくとも一つの配当を83.2521156%以上下げる必要がある**。

この変更幅は「少し調整」の範囲を超えるため、本番適用の前に配当案の選択が必要。

## 試験版の基礎配当

以下はODDS×1のBET倍率。同じ長さでは完成本数に対応する一段だけを採用し、長さ別に合計して現在のODDSを一度掛ける。FREE拡張やODDSの有無で配当を非表示にしたり、当選後に払戻しを拒否したりする処理はない。

|ライン|指定：1本 / 2本 / 3本|試験版：1本 / 2本 / 3本|
|---|---|---|
|3個|0.4 / 2 / 50|0.1 / 0.3 / 7.5|
|4個|2 / 10 / 50|0.3 / 1.5 / 7.5|
|5個|5 / 25 / 200|0.8 / 4 / 30|
|6個|10 / 100 / 500|1.5 / 15 / 75|
|7個|30 / 250 / 2000|4.5 / 40 / 2000|

2,000倍は基礎配当であり、ODDS適用後の最終配当の上限を意味しない。通常役の多くは約85%の引き下げになる。この案を小幅な修正とは扱わない。

## 盤面とFREE

- 上から1・2・3・4・5・6・7マスの28マス。1〜25はそれぞれ一回だけ配置し、残り3マスは数字を持たない初期FREE。
- 初期FREEは開始時からHIT扱い。横と2方向の斜めに、3〜7個ラインが各3本ある。長いラインの途中の3個などを別ラインとして重複加算しない。
- 番号のないFREEに対して抽選条件を明確にするため、1〜25から重複しない3つを「拡張番号」として開始時に割り当て、画面に表示する。番号と初期FREEの位置はBET確定後、抽選開始前に決定する。
- 前半5球の拡張番号HITが0 / 1 / 2 / 3個なら、追加FREEの範囲は0 / 1 / 7 / 17マス。中心も含む。
- 2個HITは6つの隣接マスをすべて持つ内側の中心だけを選べる。3個HITは前回の計算どおり、中心と盤面内の近い16マス。距離が同じ場合は固定順序を用い、端でも16マスを維持する。このため端では完全に対称な円形にはならない。候補にフォーカスすると実際の範囲を表示する。
- 中心は前半に番号HITしたマスを除いて選べ、初期FREE上も選べる。範囲の一部が前半HITと重なることはあるが、それによる遡及ODDSはない。

## ODDSと取消

ODDSは次の式だけで決まる。

`1 + 確定した範囲内の初期FREE数 + 後半3球で配置FREEに入賞した数`

初期FREE用の拡張番号に入賞したこと自体ではODDSを増やさない。範囲の各マスは一度だけ数え、置き直しは最終範囲で再計算する。選択中の中心をもう一度押すと取消し、別のマスを押すと中心を移動する。取消・再選択・同じ番号の再送・途中保存の復元でODDSや精算が増え続けることはない。

## 50〜150%の調整方法

試験版の配当表を固定し、抽選前に選ぶ2つの初期盤面候補の混合比率を調整する。25個の番号のシャッフルと8球の抽選は一様のままで、結果を見て盤面を引き直さない。

|候補|初期FREEのセルID|拡張番号を割り当てるセルID|最適配置・AUTOの理論P/O|
|---|---|---|---:|
|すその三粒|0, 20, 22|8, 11, 12|47.53269091701586%|
|三色まつり|6, 9, 24|10, 23, 25|246.85074180840772%|

セルIDは上の段から左→右の0始まり。強い候補の選択率は `(目標P/O − 47.53269091701586) / (246.85074180840772 − 47.53269091701586)`。50〜150%の全101整数設定を検証し、小数設定も同じ補間で扱う。

AUTOは後半3球を知らず、前半5球だけから条件付き期待配当が最大になる中心を選ぶ。全1,140通りの後半3球を、ラインの和集合35個に関する厳密な整数計算へまとめている。手動で最適でない中心を選んだ場合の平均払戻しは設定値より低くなり得る。

このP/Oはダンゴ通常ゲーム単体の理論値。共通Sugar・JPC、整数メダルへの丸め、ルーレットの実際の番号頻度の偏りは含まない。有限回の実測払戻率を常に設定値へ一致させる仕組みではない。

## 保存・サーバー・旧ルール

Streamingの手動配置とDownloadのサーバーAUTOを維持する。6球目を処理する前に中心を確定するため、録画の後半番号をAUTOが参照しない。新しい中心、拡張番号、FREE範囲、ODDSは従来のチェックポイントへ一緒に保存する。Downloadのwallet精算・再送防止は既存のサーバー台帳を使用する。

revision251 / 253 / 254で始まったゲームは、その25マス盤面と保存時の配当で再開する。描画、配当表、最高役、実際のworker復元、最後の一球の重複精算防止を別途検証する。

## 再現方法

- `npm run test:dango:current`：新ルール、独立した後半全列挙、101設定、AUTO、ODDS、実host・保存復元。
- `npm run test:dango`：旧ルールの試験も含めて実行。
- `scripts/dango-v262-calibrate.cpp` と `docs/dango-v262-calibration.json`：独立実装の厳密な分子・分母と相互検証用入力。
- `.github/workflows/dango-v262.yml`：Chromiumの盤面・配当・旧画面、実サーバーの10ゲーム計算、完全オフライン再開を検証する。

Windows実機へのソース更新・再起動や、本番サーバーへのBET・CREDIT操作はこの試験実装に含めない。
