# v235: 6ステーションと疑似プレイヤー

## 席
- 1抽選機につき st.1～st.6。サーバーが確認した接続順に空いている最小番号へ割り当てる。
- 抽選機ホストは席を使わない。同じプレイヤーIDの複数タブは1席。
- 一時切断後60秒は席を保持する。進行中の抽選は終了まで保持する。他の在席者は詰め直さない。
- 実プレイヤー6名で満席になると次の接続は観戦扱い。サーバー側でもBET参加を拒否する。
- 席情報は既存のshared-machine.jsonに保存する。再起動でも在席者の番号を維持する。

## 5名のTEST参加
最初の実プレイヤーが入ると、空席へ最大5名を追加する。TESTを明記する。実プレイヤーが増えると、その人がTEST席を優先して利用する。監視画面の「テスト参加5名」「テスト参加OFF」で変更できる（管理者権限が必要）。

TESTは実ゲームと同じジェリービンゴの純粋ルールを、各100BET・90%設定で実行する。全員がホストの同じ8球を受け取り、盤面の乱数は参加者ごとに別。途中参加は次のBETから。通常の9ゲーム全体・JPC・シュガー持ち越しを再現する負荷試験ではない。

TESTは実プレイヤー用の口座、精算参加者、POフィードバック、累計BET/WINに入れない。5台分の動画受信やWebGL描画を起動せず、入賞時のルール計算だけを行う。したがって6台分の映像帯域を測る試験ではない。

## 表示
クライアントはルーレットの下、ゲームタブとの間の専用40px欄に自分以外の5席を表示する。映像を覆わない。自席は「あなた st.N」。観戦者のみ全6席を表示する。

監視画面には物理抽選機の下に全6席を表示する。映像への焼き込みではなく、同じサーバーの名簿をそれぞれの画面で描画する。WebRTCの再エンコードや新しい3Dペット描画はしない。

名前・ペット設定・既存アバターの静止サムネイルを同期。公開名簿には認証情報、CREDIT、チェックポイント、他プレイヤーの口座情報を含めない。WINは当該ラウンドの獲得分で、精算確定後はサーバーの精算値を優先する。途中のWIN通知は表示専用であり口座を変更しない。

## 更新
Windows側は最新版へ更新し、.runtime・.tools・dataを残してstart-shared-machine-tunnel.cmdから再起動する。監視画面とクライアントも再読み込みする。新しいサーバーコードが動くまではステーション機能は有効にならない。
