# v239 — St別テーマカラー・最高役リーチの3D着色

v238の左右ステーション配置・ルーレット拡大・最大WIN増加番号・高配当/最高役獲得状態を引き継ぐ。旧下部40pxのSt帯は復活させない。

## 6ステーションの固定色

| 席 | テーマカラー | HEX |
|---|---|---|
| st.1 | ストロベリーピンク | `#ff5d9e` |
| st.2 | ソーダブルー | `#39d5f5` |
| st.3 | カスタードゴールド | `#ffd363` |
| st.4 | グレープパープル | `#b38bff` |
| st.5 | ミントグリーン | `#66e7b4` |
| st.6 | オレンジシャーベット | `#ff9a65` |

各Stのカード外枠/席番号とルーレット番号の発光色を揃える。プレイヤーの参加順による席番号が変わらない限り色は固定。アバター色とは独立。

## 最高役リーチ判定

従来の`visibleTabReachResults`に含まれる`hit.tier===3`の番号を全ゲームから収集（有効BET/未入賞/配当増加の候補に限定）。**全ゲーム合計の最大増加WIN番号とは独立**。たとえば12番で最高役成立、15番でより大きい通常配当なら、カードの最大増加は15番、ルーレットの着色は12番。既存キャッシュしか読まず追加の抽選・乱数・全番号シミュレーションはしない。

1ゲームでも予測キャッシュが未計算、手元とサーバーの入賞数が不一致、演出停止、BET TIME、8球終了の場合は古い色を消す。確定した最高役獲得はStカードで別途表示する。途中WINは表示専用の現行値、精算済みWINはサーバーの確定値を優先。

## サーバー物理ルーレットに直接描画

実際の25個の回転番号パネルの`onBeforeRender`だけで色を上書きする。3Dローターに装着されたパネル材質の発光と散乱を着色するため、**回転中も番号そのものに追従**する。色が同じ番号に重なる場合はst番号昇順で約0.95秒ずつ交互に表示（例：st.1ピンク→st.2水色→…）。入賞した番号は直ちに解除。JPC/BETでは着色しない。

これはWindows側の`serverHost=1`画面にだけ付ける表示用フックで、新しい3Dメッシュ、物理剛体、衝突判定、WebGLレンダラー、動画中継は増えない。既存の720p/最大60fps WebRTC映像にそのまま含まれる。クライアントごとのアバターと最高配当/リーチ状態は左右カードでDOM表示し、画像の再エンコードは増やさない。

## 安全性

`station_progress`はログイン済み参加者の最新ラウンドに紐づき、サーバーは1〜25・未入賞・最大25個・有効ボール数を検証する。最大増加WINと最高役リーチはプレイヤー自身の申告による**表示用情報**であり、配当やCREDIT台帳の承認、抽選機の入賞には使わない。古い予測（サーバーの球数不一致、12秒以上無更新など）は削除する。

## 反映

この版はサーバー/ホスト/クライアントすべての変更を含むため、Windows側を最新版に更新し、`.runtime`・`.tools`・`data`を保持したまま`start-shared-machine-tunnel.cmd`で再起動。管理画面とすべてのプレイヤー端末で再読み込みする。

## テスト

`node tests/stations-detail-v238.mjs` / `node tests/stations-highlight-v239.mjs`（最大増加WINとリーチ番号を別に処理、同一番号の色切替、元の3D回転パネル25個のみにフック、入賞/終了で解除、偽の他プレイヤー情報排除）。既存6席、2名WIN、共有同期、CREDIT、HD60の回帰検査も実行。
