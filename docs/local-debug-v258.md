# v258 — ローカルデバッグ版
SWEETS LINKの最初の画面で「ストリーミング版」「ダウンロード版」「ローカルデバッグ版」を選択できます。第三の版は `?edition=local` で直接開けます。

## ローカルでできること
- 従来の3D物理抽選機を端末内で作動させ、8球を抽選
- 抽選機の「番号指定モード」を開き、1～25番から重複のない8球を任意に入力
- 「ルーレットに戻す」で通常の物理抽選へ復帰（途中なら現行ラウンドをリセット）
- 既存の「すぐ開始」「JPCモード」「目標ペイアウト率」などのデバッグ操作
- デバッグ用BET・仮CREDIT・ローカル称号/プロフィール/チョコレートキャニオン進行を独立保存
- ローカルデバッグ版内の「版を選び直す」から選択画面へ戻れる

ローカルデバッグ版ではダウンロード版APIやストリーミング版のセッションを呼び出さず、サーバーのCREDIT、成績、プロフィール、録画に影響させません。ローカル版の保存キーは `sweets-local-debug-v258:` 接頭辞で分離します。公開版の認証トークンや管理URLは一切必要ありません。

## 実装
ゲーム本体（`optimized/app-01.js`）の変更は行いません。`index.html` の版判定内で、従来の `localEightAllowed` と `LOCAL_EIGHT_DRAW_ALLOWED` をローカル版に限って許可し、既存の `createCookieRoulette`・`setupManualNumbers` を再利用します。ローカル版ではサーバー/プロフィール送信用拡張を一切ロードしません。

`assets/local-debug-v258.js` は保存領域を提供し、`assets/local-debug-game-v258.js` が仮CREDIT、デバッグ専用UI、検証用状態参照を提供します。ソースのガード位置が変わったときは安全のため明確に起動失敗します。

ストリーミング版とダウンロード版は以前のままで、ローカル抽選へのフォールバックは起こりません。サーバー管理台帳へのクレジットの書き込みは存在しません。

## テスト
`node tests/local-debug-v258.mjs` は選択肢・両方の抽選ガード・保存領域を検証します。`node tests/local-debug-v258-browser.mjs` はサーバーAPIを持たない静的サーバーからゲームを起動し、3Dルーレット、番号指定で8球、結果、再読込と分離をChromium上で確認します。

## v267 ローカルシュガーチャレンジ
ローカルデバッグ版は、5個シュガーが貯まった次のゲーム開始時にローカル専用のシュガーチャレンジを開始する。独自の第2抽選機は起動せず、既存ローカルの8球を共用する。ルール・カード・倍率・配当はSugarChallengeRulesV254と共通。獲得した通常WINは仮CREDITの払い出しに1度だけ加算し、JPC権利は表示のみ（本体未実装）。`sweets-local-debug-v258:local-sugar-challenge-v267`に仮データを保存し、サーバー残高には送らない。ローカルのバナーで「シュガー5個（試験）」を押すと次ゲームで一括動作を確認できる。実行・隔離は`tests/local-sugar-v267.mjs`で確認する。
