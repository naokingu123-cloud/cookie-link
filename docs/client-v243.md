# v243 — クライアントの再参加・番号別予測・返却後の重複処理

## 強制BET後のNEXT
v242では全額返却を確認した後も、強制BETの間ずっとAUTO REBETを抑止していた。AUTO REBETがONなら、本人の返却済みwallet revisionを確認してから新ラウンドに1回だけBETを再登録する。0秒ではサーバーのPLAYING状態に従って開始する。AUTO OFFは従来どおり手動BET。返却前の仮の残高増加、取消ゲームの精算、二重引き落としは認めない。

## 番号ごとの増加WIN
ローダーが存在しないSweetsStationNumbersV242を参照してStモジュールを起動できなかったため、実際の公開API SweetsStationNumbersV241に合わせる。バージョン付きURLとAPI名を別に管理する。25番号は既存の盤面予測キャッシュを利用し、追加の25通り計算はしない。クッキーとシックスドロップの球数待ち（1球後と3球後、安定盤面）では次の球は蓄積のみなので、そのゲームの増加WINは0として合算する。演出処理中や予測未完了は更新待ちとし、未知の結果を0と偽らない。最高役リーチ色、倍率表示、丸め方は維持する。

## 軽量化
過去の返却通知が同じ状態通知に繰り返し付くたびに、損失・通常精算・要確認の3保存領域を毎回書き直していた。削除対象の保存データが実際に変わった場合だけ書く。Stカードも表示されないサーバー時刻等で再生成・再サイズ測定せず、表示内容の変更だけを描画キーにする。抽選速度、動画FPS設定、配当計算、強制返却の台帳処理、管理画面グラフには変更しない。

## 検証
実際の9ゲームを動かすChromiumクライアントと、隔離した実サーバー・実管理画面を組み合わせ、25番号の受信とDOM表示、強制BET後の再登録と0秒の開始、次球の反映、残高と重複保存を検証する。ホストの入賞通信はテスト用WebSocketから送るため、Windows実機GPU・iPhoneの動画再生FPSの測定ではない。

## 適用
全クライアントを再読み込みする。GitHub Pagesからの参加は公開クライアントの更新が適用される。Windowsサーバーから直接ゲームページを配信する場合は最新版を上書きし、.runtime/.tools/dataを保持して再起動・再読み込みする。旧ブラウザの保存データや口座情報は削除しない。
