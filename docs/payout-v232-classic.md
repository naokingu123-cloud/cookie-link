# v232: クッキー・キャニオン・シックスの盤面による配当調整

更新日: 2026-11-16

## クッキーリンク

初期盤面は従来のランダムな5色配置を維持する。隣り合う同色が最初から成立しない制約の中で、2マス離れた上下や斜めの色の関係を調整する。数字が消えて落下した際のつながりやすさ、数字を載せる位置、獲得したハンマーが連鎖に巻き込まれやすい位置を組み合わせる。

WILDの抽選確率は補充1回の候補がある場合に0.6%、ハンマー予告は予告可能な列・予告機会ごとに3.5%で固定する。設定が高いことだけを理由に予告アイコンやWILDの抽選確率を増やさない。連鎖によるハンマー獲得、持ち越した予告、補充回数の違いに伴う自然な個数差は残る。

ハンマーの色・獲得条件、配当表、3・10・50・200・500倍の全消し配当は維持する。盤面の評価は現在の状態だけを参照し、今後サーバーから届く実際の抽選番号は参照しない。

## チョコレートキャニオン

通常の12行×7列の初期地形は、12種類の左右対称パターンから選ぶ。各パターンは既存の3〜6マスのコンパクトな形だけで構成し、上下反転と4色の置き換えを組み合わせる。100mごとのボーナス層にまたがる薄い地形や、掘削後の補充は既存の形状生成でつなぐ。

以前は設定によって鉱石・アイテムの密度と高ランク鉱石の割合を変えていた。今回は生成時の個数・種類の抽選を設定から独立させる。生成された鉱石の一覧を維持したまま、掘削で露出しやすい位置との関係を重み付けする。鉱石価値は既存の各ランクの値・表示範囲の中から、生成時に抽選する。価値の抽選重みも調整するが、入賞後の獲得額に倍率を掛けて補正する処理は加えない。

同一の初期seedで設定だけを50・90・150%に変えた180組を検査し、初期地形の色、鉱石とアイテムの個数・種類、ドリル番号、生成後の乱数状態が一致することを確認した。変わるのは鉱石の配置先と事前に決める価値である。既存のオッズアップ・鉱石ランクアップ・100mボーナス・保存深度の規則は維持する。

## シックスドロップ

既存の6種類の左右対称な空きマスパターンと、25番号の対称な配置枠を維持する。ペイアウト設定によって初期の空き数、色数、CHANCEラウンドの確率、役の配当を増減しない。

調整には、生成時の同色同士の近づきやすさ・離れやすさを使う。最初から4個以上の同色消去や役が成立しないこと、初期盤面が重力で勝手に崩れないこと、25番号が重複しないことを維持する。現行の穴・補充ルールを実際に適用したコードで係数を再調整した。

## 試算

実ブラウザと同じ順番で`CookieUpgradePatch.patch`と`index.html`内のシックス上段補充パッチを適用したゲームコードを使用する。MISSだけでなく、通常HIT後に初期盤面より上段が減った場合の補充も含める。盤面用とは独立した乱数列で1〜25から異なる8番号を一様に選ぶ。通常ゲームの直接配当だけを集計し、共通ワンダーシュガー・JPC配当は含めない。

| 設定 | クッキーリンク | キャニオン | シックスドロップ |
| --- | ---: | ---: | ---: |
| 50% | 47.79% | 49.70% | 49.76% |
| 70% | 66.02% | 69.78% | 71.16% |
| 90% | 89.10% | 89.78% | 91.52% |
| 110% | 114.48% | 113.52% | 112.00% |
| 130% | 124.33% | 126.32% | 137.26% |
| 150% | 152.77% | 149.52% | 154.91% |

50・90・150%は各6,000ゲーム、70・110・130%は各2,000ゲーム（キャニオン70・110%のみ各4,000ゲーム）。有限回の試算のためばらつきがある。各ゲームや実物の抽選機で、設定値そのものの実績を保証する表ではない。キャニオンの深度とクッキーの持ち越し状態によるゲーム間の相関もある。過去のv26の試算は、現在の上書きパッチを反映していないため今回の数値には流用していない。

シックスはゲーム間で盤面を持ち越さないため、各6,000ゲームの標準誤差から求める正規近似の95%信頼区間も記録する。設定50%は47.95〜51.57%、90%は87.00〜96.03%、150%は148.16〜161.66%である。クッキーとキャニオンは持ち越し状態の相関を補正していないため、単純なゲーム単位の標準誤差を正式な信頼区間として扱わない。シックスの200ゲームごとのブロック平均・ブロック標準誤差もJSONに保存した。

生データ、各試算の完全なコマンド、標準誤差、再現条件は`docs/payout-v232-classic-statistics.json`。例:

```sh
node tests/payout-v232-classic-sample.cjs cookie 6000 90 832771
node tests/payout-v232-classic-sample.cjs canyon 6000 150 832771
node tests/payout-v232-classic-sample.cjs six 6000 50 832771
node tests/payout-v232-classic-rules.cjs
```

ルール試験は、実Engineによる予告/WILD確率の設定非依存、12種類すべての対称地形、設定変更時の在庫不変、6種類のシックス盤面の安定性、番号25個、色選択補助が入力盤面を変更しないこと、ブラウザ本体と単体ソースの一致を確認する。さらに50・90・150%の4seedずつ、計12ゲームで実際の`SixBallCandyEngine`と高速サンプラーを比較し、8球の処理数、WIN、最終盤面、ラウンド番号、タイルID、シュガー獲得が完全に一致することを確認する。統計用の大量試算は通常CIには追加しない。
