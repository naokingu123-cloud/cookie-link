# v246 — 番号別配当の順次更新・非表示時の完了・映像と演出の描画改善

## 1〜25番号の順次更新
全ゲームの次盤面を待たず、既存リーチ計算が完了したゲームの増加WINを先に送る。未完了ゲームを0配当と断定せず、確認済み分の暫定合計として表示する。後続ゲームの予測が確定すれば合算を更新する。既存の約1秒間隔・変化時送信を維持し、新しい25通りのゲームシミュレーションは追加しない。

暫定値には点線枠と確定ゲーム数の説明を付ける。全体合計も既知の参加者分から表示し、未確認分が残れば暫定扱い。全体の最大番号と配当帯到達色は全ゲーム確認まで確定扱いにしないが、個別ゲームで確定した最高役リーチ番号のSt色は反映可能。次の入賞、ラウンド切替、精算、古い予測では元の失効条件を守る。

## ブラウザー非表示時の進行
非表示タブでは描画を続けるのではなく、60ms周期の軽量Workerで必要な処理を起こす。既存のエンジン待機タイマーを補助し、画面更新に結び付いていたジェリー・ポップコーン・ワッフルの内部進行を、画面描画なしでも実行する。カステラの表示時計も同じ経路に対応する。チョコレートキャニオンの配当表示時計と、最終盤面の表示待ちも、非表示を理由に永久停止しない。

リザルト→払い出し→完了は既存の状態遷移を使い、CREDITの確定は引き続き既存のサーバーACK処理に従う。手動一時停止、取消処理、二重精算防止、ローカル8球禁止は維持する。OSがページやアプリの実行を完全停止した場合の動作は保証しない。

## クライアント映像と大盤面
- 配信設定だけでなく、元のサーバー抽選機描画に残っていた30fps上限を見直し、受信者がいる場合は最大60fpsを目標とする。描画処理が重い場合は30fpsへ落とし、安定後に60fpsへ戻す。動画キャプチャ側の既存24/30/60fps制御とも連動する。抽選の物理刻み・回転速度・番号・配当計算は変更しない。
- キャニオン、シックスドロップ、ジェリー、ポップコーン、ワッフル、カステラの大盤面描画は、選択中のものを最大60fps目標とし、描画負荷によって30fpsへ調整する。未選択の小盤面は、通常UI更新1回あたり最大2面ずつ描く。全部を一度に描く負荷を分散し、取り残した小盤面は短い遅延で更新する。
- WebRTCでは対応ブラウザーに限り80msの受信ジッターバッファ目標を指定する。非表示で動画のフレーム通知が止まっても、それだけで通信障害とみなして接続を作り直さない。復帰直後は既存動画に短い猶予を与える。
- JPEG代替映像は最新の受信画像を画面更新タイミングに合わせて提示する。画像要素は安定して再利用し、画面全体のDOM監視を毎フレーム起こさない。非表示中はJPEGの追加受信・デコードを止める。従来の15fps代替配信そのものを60fps化する変更ではない。
- WebM代替映像の軽い遅延は穏やかな追従で戻し、小さな遅延のたびに再生位置を飛ばさない。大きな遅延は従来同様に上限を設けて修復する。
