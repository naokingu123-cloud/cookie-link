# Crystal JPC v306：ルールと期待値の設計根拠

新しい選択式JPCは、初期30球・通常ポケットの累計配当・JP5HIT条件を維持し、追加球を **+1 / +1 / +4 / +8** に調整する。25穴が独立に等確率で選ばれるモデルで、**JPC1回の平均獲得配当は251.7010859**。目標250との差は+0.68%となる。

この期待値はJP不成立時の配当も含む。物理ルーレットで測定した実績値ではなく、各穴が毎回独立に1/25で選ばれるという仮定の下での設計値である。

## ルール

- 開始時の残球は30。抽選ごとに1球を消費する。
- 25ポケットのうち、JPはポケット番号1、追加球は6・11・16・21に配置する。特殊ポケットは5穴間隔。内部配列の0始まりインデックスでは、それぞれ0と5・10・15・20となる。
- 追加球ポケットはそれぞれ+1・+1・+4・+8。入賞するたび、消費後の残球に加える。+1は1球を返すため、抽選前と比べた残球は据え置きになる。
- 残り20ポケットには、同じポケットへの累計HIT数に応じた値を設定する。各入賞で過去の累計値を重ねて支払わない。
- 残球がなくなるまで継続する。総抽選球数やJP倍率に任意の上限を追加しない。

| 同一通常ポケットのHIT数 | 色 | そのポケットの累計値 |
|---:|---|---:|
| 0 | 未入賞 | 0 |
| 1 | 青 | 1 |
| 2 | 青緑 | 2 |
| 3 | 緑 | 3 |
| 4 | 黄緑 | 4 |
| 5 | 黄 | 6 |
| 6 | 橙 | 8 |
| 7 | 赤 | 10 |
| 8以上 | 紫 | 15 |

例えば同じ通常ポケットへ7回入賞した場合、そのポケットの最終値は10であり、1+2+3+4+6+8+10ではない。通常20ポケットの最終値の総和を `S`、JP穴の累計HIT数を `J` とする。

```text
J < 5 : 最終配当 = S
J >= 5: 最終配当 = S × 5 × (J - 4)
```

| JP穴HIT数 | JP表示倍率 | Sに対する最終配当倍率 |
|---:|---:|---:|
| 0〜4 | 不成立 | 1 |
| 5 | ×1 | 5 |
| 6 | ×2 | 10 |
| 7 | ×3 | 15 |
| 8 | ×4 | 20 |

`referenceJP: 500` はユーザー指定の参照JP額を記録するもの。旧JPCの累積HIT配当に500を掛ける仕組みとは別のルールであり、**新JPCのSへ500を加算したり、Sを500倍したりしない**。ここでの251.7010859は、上記の累計値と最終式から直接計算した値である。

## 調整結果

通常配当、初期30球、JP条件・倍率は固定し、追加球4個だけを変更した。

| 追加球 | 平均最終配当 | JP成立率 | 平均抽選球数 |
|---|---:|---:|---:|
| 原案 +3 / +3 / +5 / +10 | 5,675.6533 | 55.2847% | 187.5000 |
| +2 / +2 / +3 / +7 | 211.6727 | 16.0041% | 68.1818 |
| +1 / +1 / +5 / +7 | 235.9120 | 16.3145% | 68.1818 |
| +1 / +2 / +3 / +8 | 242.0613 | 16.3052% | 68.1818 |
| **採用 +1 / +1 / +4 / +8** | **251.7011** | **16.4204%** | **68.1818** |
| +3 / +3 / +4 / +5 | 274.0084 | 20.0215% | 75.0000 |

正整数1〜10の追加球4個、追加球合計25未満という範囲で、順序を同一視した全461組を走査した。採用案はその範囲で最も250に近く、最初の2ポケットが同じ追加球数である形も維持する。

採用案のJP成立時の平均配当は1,252.3426、不成立時は55.1109。全体平均への寄与はそれぞれ205.6396と46.0615で、その和が251.7011となる。

追加球の合計をBとすると、1抽選あたりの平均追加球はB/25。平均総抽選球数は `30 / (1 - B/25)` となる。原案はB=21なので187.5球、採用案はB=14なので68.1818球。原案では長く続いた回ほど通常累計値とJP倍率の両方が増えるため、各平均値を単純に掛けて期待値を見積もることはできない。

## 母関数による計算

Pythonスクリプトは乱数を使わず、確率母関数から期待値を数値計算する。以下の式は無限に継続しうる全抽選を含み、掲載値は倍精度浮動小数点で求めた数値解である。

通常ポケット1個のHIT数をH、JP穴のHIT数をJとする。1球が抽選され、その追加球から生じる抽選もすべて含めた母関数をF(x,y)とすると、

```text
F(x,y) = [19 + x + y + Σ_b F(x,y)^b] / 25
G(x,y) = F(x,y)^30
```

となる。19は注目した通常ポケット以外の通常穴、xは注目した通常穴、yはJP穴を表す。追加球bの入賞は、同じ分布を持つ子の抽選をb個生む。初期30球は30個の独立した抽選系列なので30乗になる。B<25のためこの分岐過程は平均的に縮小し、終了確率は1、平均総抽選数は有限である。

必要な係数を次のように置く。

```text
p_h = [x^h] G(x,1)           = P(H=h) = P(J=h)
q_k = [z^k] G(z,0)
P(H=h,J=j)                  = binom(h+j,h) q_(h+j)
E[J · 1{H=h}]               = (h+1) p_(h+1)
E[J]                        = 30 / (25-B)
```

Fはx+yだけを通じて変化するため、同じ総次数の係数は二項係数で配分できる。またGのx偏微分とy偏微分が等しいので、上記の混合期待値が得られる。

通常ポケットの累計配当をg(h)とし、`d_h=15-g(h)`（h=0..7）とする。g(h)は8以上で15なので、次で期待値を求められる。

```text
D   = E[g(H)]       = 15 - Σ_(h=0..7) d_h p_h
K   = E[g(H)J]      = 15 E[J] - Σ_(h=0..7) d_h (h+1) p_(h+1)
L_j = E[g(H)1{J=j}] = 15 p_j - Σ_(h=0..7) d_h binom(h+j,h) q_(h+j)
```

JP倍率関数は、`5J-20`にJ=0..4の補正を加えると表せる。

```text
f(J) = 5J - 20 + Σ_(j=0..4) (21-5j) · 1{J=j}
E[最終配当] = 20 × [5K - 20D + Σ_(j=0..4) (21-5j) L_j]
```

したがってpは8次まで、qは最大 `h+j=7+4=11` 次まであれば足りる。**11次という制限はHIT数・抽選球数の上限ではない。** 高次項はそれより低い次数の係数に影響せず、8以上の通常HITと5以上のJP HITは上の期待値式でまとめて含めている。

係数はFのゼロ多項式から上の固定点式を反復し、各反復で必要次数まで畳み込むことで求める。隣接反復の係数差の最大値が2e-17未満になるまで反復する。10,000反復で収束しない場合は計算エラーとするが、これは数値解法の停止条件であり、ゲームの抽選上限ではない。

`--check` は採用案・原案の値を再計算し、保存JSONの構成と統計値を照合する。追加球をすべて0にした場合には必ず30抽選で終わるため、独立した多項分布の直接総和とも比較する。この対照の配当期待値は24.7979676654で、両手法の差は約2.2e-11だった。

## 独立シミュレーション

母関数とは独立に、C++で球を1球ずつ入賞させる500万回のシミュレーションを実施した。seedは20261125、`std::mt19937_64`と`uniform_int_distribution(0,24)`を使用。抽選回数・JP倍率の打切りはない。

| 項目 | 結果 |
|---|---:|
| 平均配当の推定値 | 251.9882256 |
| 標準誤差 | 0.3586361 |
| 平均の95%信頼区間 | 251.2853〜252.6912 |
| 母関数の数値解 | 251.7010859 |
| JP成立率 | 16.4291% |

母関数の値は独立シミュレーションの95%信頼区間内にある。原案も別seed・100万回で検証し、平均5,684.7151、95%信頼区間5,662.7925〜5,706.6378となり、母関数の5,675.6533と整合した。

| 分位 | 総抽選球数 | 最終配当 |
|---:|---:|---:|
| 50% | 60 | 53 |
| 75% | 82 | 87 |
| 90% | 110 | 515 |

採用案でも100球を超える回は約13.55%、200球を超える回は約0.563%ある。短い球数上限を追加すると、この設計期待値から変わってしまう。500万回で観測した最大球数556・最大配当39,000は標本中の記録であり、仕様上限ではない。

## 再現手順

リポジトリのルートから実行する。Python 3とC++17の標準ライブラリ以外は不要。スクリプトはゲーム状態・配当設定を書き換えない。

```bash
# 短時間のCI用チェック（乱数シミュレーションは実行しない）
python3 scripts/jpc-crystal-v306-expectation.py --check

# 採用案・原案の構成と理論統計をJSON出力
python3 scripts/jpc-crystal-v306-expectation.py

# 追加球461組の比較。統計ファイルを再生成
python3 scripts/jpc-crystal-v306-expectation.py --scan --out /tmp/jpc-crystal-v306-theory.json

# 独立シミュレーターをビルド
c++ -O3 -std=c++17 scripts/jpc-crystal-v306-simulate.cpp -o /tmp/jpc-crystal-v306-simulate

# 採用案500万回と原案100万回
/tmp/jpc-crystal-v306-simulate 5000000 20261125 1 1 4 8 > /tmp/jpc-crystal-v306-selected.json
/tmp/jpc-crystal-v306-simulate 1000000 918273645 3 3 5 10 > /tmp/jpc-crystal-v306-original.json
```

詳細な保存結果は `docs/jpc-crystal-v306-math.json`。`rules`には実装と照合するためのポケット位置・初期球数・追加球・通常配当・JP条件を格納している。`--check`単体は保存データと数理モデルの一致を検査し、ブラウザー内の実装との一致はゲーム側テストで別途確認する。

保存したシミュレーションはg++ 14.2.0 / GNU libstdc++で実行した。`uniform_int_distribution`の整数への写像はC++標準ライブラリ間で同一とは限らないため、同じseedでビット単位の再現が必要な場合は同じ標準ライブラリを使う。別実装でも等確率モデルの期待値と統計的には一致する。
