# v237: 公開リンクからのゲスト参加

参加者へ送るURLは https://naokingu123-cloud.github.io/cookie-link/ です。GitHubアカウント、メール登録、パスワード、管理者トークン、接続先の手入力は不要です。既存の匿名セッション発行APIを利用し、初めて開いたブラウザごとにサーバーが専用のプレイヤーIDと認証トークンを自動発行します。

## 変更
- 引数なしの公開リンクは常に public-01 に接続します。受信者の古いルーム設定は使いません。
- 公開設定 shared-endpoint.json を優先して取得。5秒で取得を打ち切り、未取得なら現在の固定公開サーバーへ接続します。過去のローカル接続先へは戻しません。
- ブラウザ保存が拒否・容量不足でも、同じページの再試行中はメモリ内で同一セッションを維持します。ページを閉じた後の復元には保存領域が必要です。
- プレイヤー認証情報を接続先別に保存し、別のサーバーを指定したリンクに既存の認証情報を送りません。現在の公開サーバーの既存プレイヤーは移行してIDを保ちます。
- 6席制限、7人目以降の観戦、疑似プレイヤー停止、実プレイヤーWIN共有、ホストの管理者認証、物理抽選は変更しません。

## 条件
GitHub Pagesは画面の配信元であり、Windowsの抽選サーバーと公開トンネルが稼働している必要があります。停止中にローカル抽選へ切り替えることはありません。Cloudflare Access等の外部ログイン制限をフロントエンドで回避・解除するものではありません。公開APIが外部認証で遮断されている場合は、Cloudflare側でプレイヤー用経路の公開設定が必要です。管理APIのトークン保護は維持してください。

公開リンクに adminToken・token・playerId は入れないでください。新しい参加者は通常リンクだけを開きます。更新前から開いている端末は再読み込み（WindowsはCtrl+F5）してください。サーバーが既にv236なら今回の初回参加対応はGitHub Pages側の更新で利用できます。全ファイルをWindows側にも更新する場合は .runtime/.tools/data を残してください。

## 検証
- guest-entry-v237.mjs: 初回接続、古いルーム除外、タイムアウト復旧、保存不可・容量不足、認証情報の接続先分離、既存セッション移行。
- guest-login-v237.mjs: 実際のClient.initializeとHTTP/WebSocketサーバーを利用した未登録7端末、独立ID、st.1～6、満席観戦、管理API拒否、再訪ID保持、6人分のBET。
- guest-public-probe-v237.mjs: 公開サーバーのhealthとCORSプリフライトの読み取り専用確認。停止・外部認証等で確認できない場合は結果に明示し、成功として扱わない。
