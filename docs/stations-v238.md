# v238 — ルーレット脇のステーション情報

## 配置
旧40pxの下段ステーション欄と44pxの予約余白を撤去。クライアントは他の5席をルーレットの左右に交互配置する。ルーレットは横・縦の余白を減らして大きくし、中央にカードを置かない。自分のst番号は中央下に表示する。高さが足りない横画面ではサイド欄をスクロールできる。

サーバー管理画面も既存の抽選機iframeの左右に全6席を表示する。iframeは移動・再生成せず、映像配信へ文字を焼き込まない。クライアントごとに自分のカードを除外でき、動画の再エンコード負荷を増やさない。

## 各カード
- アバター、st番号、プレイヤー名、現在WIN。
- 次HITで最も配当が増える番号と `＋増加見込み`。配当総額ではなく現在からの差額。同率の番号は保持し、表示幅の関係で代表番号と「ほか」を表示。詳しい説明はカードのtitle/読み上げに含める。
- プレイ中、BET TIME、次ゲーム待ち、再接続待ち、精算完了。実際に獲得した高配当（各ゲーム3倍以上）、超高配当（10倍以上）、最高役は別の強調色で表示する。

最高役はゲームの実状態・既存イベントを読む。ポップコーンは3回以上全消し、ジェリーは12ライン、ワッフルはリバーサル、カステラは全焼など、未来の最高役リーチを獲得扱いにしない。

## 予測の計算
有効な全ゲームの既存 `visibleTabReachResults` キャッシュを読む。同じ未入賞番号について、`medalWin(BET, HIT後倍率) - medalWin(BET, 現在の基準倍率)` を合計して最大を選ぶ。端数処理も既存のmedalWinに合わせる。新しく25番号をシミュレーションせず、乱数も消費しない。

1ゲームでも必要なキャッシュが未計算・更新中なら部分的な合計を最大と偽って表示せず「更新中」とする。サーバーの入賞が先行したとき、8球終了時、再接続待ち、次ラウンド、12秒以上通知が止まったときは予測番号を外す。画面更新中に一時的に番号が消えるのはこのため。

## 通信・安全性
既存station_progressへ小さなdetailオブジェクトを添付。1秒単位で変化があったとき送信し、無変化でも8秒に1回だけ生存確認する。サーバーは認証された送信元と参加ラウンドを確認し、番号・配当・状態・ゲームIDを制限。公開名簿へ任意文字列、他人の残高、盤面、秘密情報を追加しない。予測/獲得状態は表示用の自己申告であり、CREDITや配当計算の根拠には使わない。

疑似プレイヤー停止、6人制限、ゲスト参加、物理1倍速、入賞同期、BET、CREDIT、HD60配信は維持する。今回の変更は配当ルールや未来の抽選番号を変更しない。

## 反映
Windowsサーバーを更新して再起動し、管理画面と全参加者のブラウザを再読み込みする。.runtime / .tools / data は残す。GitHub Pages更新だけではWindows側の情報中継は更新されない。
