# v276 — 発射のばらつきと三角ストッパー

## 変更

`optimized/app-01.js` 内の本番 `PHYSICS` を変更した。同じコードをストリーミングの抽選ホストと `server-download-recording-v255.mjs` の録画計算が使用する。

- 各球の発射速度、角度、回転量、発射口内の位置、床との間隔、内向き成分、わずかな上向き成分、縦軸回転をシード付き乱数で決める。発射時に一度だけサンプルし、JPCの発射待機や録画計算で引き直さない。
- 通常の速度幅は基準8.82に対して±0.62（旧±0.25）、角度幅は±0.082 rad（約4.7°、旧約2°）、回転量は基準の0.85〜1.15。発射口は角度±0.012 rad・半径±0.018モデル単位の小さな幅に収める。
- 3個のストッパーの120°間隔、三角形の平面寸法0.78×約0.4503、元の角丸0.035、向き−5°は維持。中心半径を3.57から3.50へ0.07だけ寄せ、既HIT穴に載った球が肩に触れやすくする。
- 外側へ下がる屋根を45°から約25.2°へ低くし、回転盤に運ばれる球が入る側の0.23モデル単位を滑らかな曲線で面取りする。見た目と当たり判定は従来と同じ `stopperMesh` から作る。
- ストッパー専用の反発係数は0.02から0.68、摩擦は0.035から0.008。三角メッシュの隣接面が同じ接触へ重複したブレーキを掛けないよう、その球とそのストッパーの最深接触を1つ採る。床・穴・球同士の接触処理は変更しない。

力を追加する補助処理、球の瞬間移動、番号を選ぶ処理、既HIT番号だけを特別扱いした誘導は追加していない。塞がれた穴の実際の球コライダー、回転盤、三角ストッパーの接触によって別の空き穴へ移る。必ず隣の番号へ入る保証は設けない。

## 物理確認

`node tests/roulette-motion-v276.mjs` は本番のCannonとPHYSICSを読み、120Hzで計算する。ブラウザーや公開サーバーを使用しない。

| 確認 | 結果 |
|---|---|
| 128回の発射サンプル | 速度8.212〜9.423、角度2.0421〜2.2020、回転0.8523〜1.1472。位置・内向き成分にも幅がある |
| 同じシードの再計算 | 発射サンプルが完全一致。決定済みサンプルを発射する際に乱数を追加消費しない |
| 3方向の通常接触、2速度 | 接触後の速度が接触直前の74.4〜91.8%。各方向で外向きの速度を持って離れる |
| 同条件のv275参考値 | 半径3.65・速度5では37.95%、半径3.80・速度8では49.63% |
| 3方向の逆向き接触 | いずれも接触を抜け、滞留しない。正面に近い逆接触なので速度維持は約49% |
| 既HIT穴上の球 | 3方向×「盤と一緒に移動／初速0・隣接穴も塞がれている」の6条件で、1.70〜1.90秒後に実際の空き穴へ入賞 |
| 押し出しの連続性 | 既HIT穴からの6条件で1ステップ最大移動量0.034〜0.050モデル単位、球の中心高は0.35未満、fault0 |

通常接触は半径3.65・速度5と半径3.80・速度8の代表条件で、速度比は接触から離れて9ステップ後の値。低速・正面衝突・先端への衝突など、すべての接触で同じ速度比になるわけではない。正面の減速は残しながら、周回する球がかすめる接触を優先して改善した。

詳細な数値は `roulette-motion-v276-qa.json` に収録。追加の本番8球録画はseed27601（109.04秒、3273フレーム）とseed8013（111.83秒、3356フレーム）の両方が8個の異なる番号で完走し、fault0。計算時間はそれぞれ43.5秒・42.8秒だった。同一シードの録画全体の再現性は既存の `tests/download-v255-recording.mjs` でも検査する。旧録画の再生形式、球の保持、CREDIT、BET、配当計算、クライアントで抽選しないガードは変更していない。

## 適用範囲

公開ページの更新に加え、ストリーミングの物理ホストやダウンロード録画を計算するWindowsサーバーは最新ソースへの更新と再起動が必要。既に確定して保存されている録画は、保存済みの動きをそのまま再生する。

物理パラメーターの変更で軌道と入賞列は変わる。ここでのシード付き検査は再現性と完走・接触の確認であり、25番号の長期的な一様性やゲーム全体のペイアウト率を再較正したものではない。
