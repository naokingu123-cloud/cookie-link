# v240 — 管理者BET開始・非アクティブ進行・全6席左側表示

## 管理画面: 「BET TIME 開始」

抽選サーバー管理画面の物理抽選機タイトル横にボタンを設置。管理者トークン付きの `POST /api/admin/machines/{machine}/bet-now` のみが操作可能で、ゲストリンクや一般プレイヤー画面からは実行できない。

- 待機中: 物理ホストが接続していれば、その時点からサーバー基準のBET TIMEを開始する。接続前ならホスト再接続を待つ。
- BET受付中: **既存のラウンドIDを維持して**残り時間を所定のBET時間（標準20秒）に戻す。既存のBET/CREDIT予約を解除・再請求しない。待機中の接続済み適格プレイヤーも受け付ける。
- 8球抽選中: 現在の物理抽選と確定済み入賞は中断しない。「次のBET TIME開始」を一度予約し、8球終了後、最短1.5秒の終了処理時間を経てサーバーが次のラウンドを開始する。再連打してもキューは増えない。
- 抽選終了後: 完了済みラウンドを履歴に保管し、新しいBETを開始する。未精算の参加者は引き続き履歴ラウンドを参照できる。
- ホストが切断されたとき: ホスト接続待ちを返し、古いラウンドを破棄しない。入賞球をランダム補完しない。

## 非アクティブ時の進行

- 時刻・参加受付・ラウンド進行は**サーバー時計**で継続する。
- Windowsのサーバー抽選機は、ページが非表示の場合も既存のキャプチャWorkerから同じ物理ルーレットの演算・描画を1回ずつ進める。表示状態では通常のrequestAnimationFrameに戻る。物理速度1倍、6席、720p最大60fps、番号のSt色切替を維持。
- 物理抽選機が非アクティブでも一度入賞した球の二重報告や不正な追加球は発生させない。Workerが存在しない環境は軽量な代替タイマーを使用し、停止したブラウザは再接続時に同期する。
- クライアントは共有ラウンド中、タブ非表示やメニュー表示だけではゲームエンジンを一時停止しない。復帰時は既存コントローラからサーバーの結果・WIN・CREDITと照合する。手動で一時停止を指示した場合は尊重する。
- **制限:** iOSやAndroidのOSがバックグラウンドのタブ・ブラウザプロセスそのものを凍結/終了すると、フロントエンドで物理演算・アニメーションをリアルタイム実行し続けることは保証できない。サーバー側の時計と確定済み結果は存続し、再開時に同期する。Windowsホスト自体がスリープした場合は、ブラウザだけで演算を継続できない。

## 6席は左側の縦1列

**自席も含めて** st.1〜st.6 を全件固定順に表示。右側・下部の分散カードは廃止する。各カードの可視情報は「Stナンバー・アバター・名前・現在のWIN」のみ。空席は空席として表示し、自己席は固定テーマカラーと外枠で区別。旧「最大増加番号」「最高役の状態」の表示文字は除去するが、サーバー内部のリーチ計算・回転ルーレットの最高役リーチ番号発光色は保持する。

管理画面も物理抽選機を再ロードせず、iframeの左側に同じ6席を縦1列で重ねる。映像を再エンコードせず、最大60fpsの配信に余計な負荷をかけない。
