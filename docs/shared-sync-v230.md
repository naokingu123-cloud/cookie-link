# v230: リザルト後の操作復帰と定常更新の負荷軽減

更新日: 2026-11-16  
版: `20261116-v230-result-input-performance`

## 最初のリザルト後に操作できなくなる原因

実際の`renderRoundResult`は、リザルトを表示するときにarena・ゲームタブ・ゲーム・操作パネルを`inert`にして背景操作を止める。元の値は`resultInert`へ保存し、リザルトを閉じるときに戻す構造だった。

共有ゲームのcontrollerは、次ゲームを用意する際にリザルト要素の`hidden`を先にtrueへ変えていた。元の描画処理は「まだリザルトが表示されている場合」にしか入力の復元を行わないため、次の描画が来ても`inert`が残った。phaseがreadyでリザルトが非表示になっていても、ゲームタブやBET操作が反応しない経路を再現した。

v230はリザルトを強制的に非表示にする前に、リザルトが所有する入力制限を解放する。元から操作不可だった領域はその状態を維持する。結果表示中にメニューを開いた場合はメニューの入力制限を保持し、その保存済みの復元先だけを補正する。メニューを閉じたときに、古いリザルトの制限を復活させない。JPCとメニューが重なる場合も、それぞれの所有権を保つ。

## BETボタンの不要な更新を省く

資金の確認は続けながら、disabled・aria-disabled・灰色クラス・title・中央BETラベル・AUTO REBETのチェック状態が現在値と同じならDOMへ書き込まない。独自のキャッシュだけで判定せず実際のDOM値と比較するため、元のHUDがボタン状態を変更した場合は次の確認で正しい状態へ戻せる。

同じ状態の確認を100回行う実コード試験では、対象コントロールへのsetter・属性・クラス更新操作が8,600回から0回になった。これは該当更新処理の計測であり、端末全体のCPU使用率やFPSの改善率を表す数値ではない。

## 映像更新の負荷軽減

映像の状態確認で、同じ動画の表示指定、再接続表示の同値更新、ローカル抽選機の停止処理を繰り返さないようにする。ローカル抽選機が別処理から再開された場合や描画オブジェクトが交換された場合は、必要な停止処理を適用する。

ホストの状態通知がまとめて届いた場合も、映像の準備完了通知と視聴要求が大量に重ならないようにする。健康な既存の映像はラウンド境界を越えて維持する。接続やフレームの異常を検出した場合の復旧は維持する。

実映像制御コードを60秒・2ラウンド動かしたVM試験では、初回表示後の同じ停止指示200回、再接続文言の同値更新200回、datasetとbody class操作各600回、旧映像要素の全体走査400回を、それぞれ0回にした。他の処理からの再開やdriver・setter交換時には再停止する。100件の同時snapshotに伴う追加告知は100件から0件へ、健康な視聴者への同じホストの30告知に伴う追加要求は60件から0件へ減らした。新しいソケットへの告知と3秒ごとの定期告知は維持する。

12回の再接続後も使用中のpeer・MediaSource・動画listener・フレームcallback数が一定であることを確認した。WebM非対応の環境では、その環境で使えないrelayを購読しない。

## 検証

- `tests/shared-v230-client-lifecycle.mjs`: 実Arcade/core、実リザルト描画・メニュー処理で3ゲームを実行。結果中の背景操作禁止、終了後の操作復帰、メニュー・JPCの入れ子、元からの入力制限、定常時の更新回数、HUD上書きからの復旧を確認する。
- `tests/shared-v230-video-lifecycle.mjs`: 複数ラウンドをまたぐ映像の定常更新と再接続について、描画停止・表示・通知・接続の回数と復旧を確認する。
- `npm run check`と`npm run test:shared`で、従来の同期、BET予約、WIN精算、再送、連続ゲーム、映像復帰を確認する。

独立した3ゲームのcontroller計測では、保留タイマーは3件で一定、各1秒のコールバック数は16〜17回、HTTP状態取得は1〜2回であり、この経路でタイマーの際限ない増殖は再現していない。今回確認できた入力制限の残留と、反復更新の負荷を修正対象とした。

## v229までの変更を維持

各枠BET操作時のCREDIT即時控除、中央BETとAUTO REBETの一度だけの控除、ゲーム終了時のWIN加算、残高不足時の無効化、20秒のサーバーBET TIME、抽選機動画の表示領域とデコード復旧を維持する。残高の初期化版はv228のままで、今回の更新でCREDITを100万へ戻すことはしない。

Windows側のファイルも最新版へ更新し、ホスト画面とプレイヤー画面を再読み込みする。v229の20秒設定をまだ適用していない場合は、サーバーも既存の`start-shared-machine-tunnel.cmd`から再起動する。`.runtime`・`.tools`・`data`は保持する。
