## 画面の変更

- 旧瓶の側面画像を描く `.field::before` / `::after`、旧反射線、旧 Canvas の角丸枠を取り除き、v278 の瓶画像に統一した。
- メイン盤面のドロップを半径 14.75、中心間隔 29.5 に拡大し、瓶の開口に合わせて中央位置を調整した。盤面・クリック位置・移動演出・リーチ表示は同じ座標計算を使う。
- 「全消し」と配当を瓶と同じ幅 312 px にまとめ、間隔を縮めた。外側の水色の枠とガラス装飾を取り除いた。上部のルーレット表示は変更していない。
- メイン瓶の直下に「消去合計」を追加した。全消し配当と同じアニメーション値から表示数を計算するため、消去した個数が配当と同期して連続的に増える。終了時には実際の累計と一致する。
- 「3-2-1-1-1」の画面表記を削除した。実際の 8 球を 3・2・1・1・1 球のまとまりで処理するルールは維持する。
- 配当表の個数を `×1`、`×2` 形式に統一した。直線は 4 個の一列、三角は 1・2・3 個の三段、ヘキサゴンは中央が空いた 6 個の輪を、実際のドロップ画像で描く。
- 全消しの獲得回数・獲得済み配当、継続表示、次回へ持ち越す配当、ミニ盤面の全消し演出を維持した。

## 役配当

新規ゲームはルール revision 280 を使う。表の値は、そのゲームで成立した各役の**累計個数に対する BET 倍率**。直線・三角・ヘキサゴンは個別に計算し、それぞれ小数メダルを切り捨ててから合算する。全消し配当は別途加算する。

| 成立数 | 直線 | 三角 | ヘキサゴン |
|---|---:|---:|---:|
| ×1 | 0.2 倍 | 0.5 倍 | 1 倍 |
| ×2 | 0.5 倍 | 2 倍 | 4 倍 |
| ×3 | 1.5 倍 | 4 倍 | 8 倍 |
| ×4 | 2.5 倍 | 7.5 倍 | 15 倍 |
| ×5 | 4 倍 | 12.5 倍 | 25 倍 |
| ×6 | 5.5 倍 | 17.5 倍 | 35 倍 |
| ×7 | 7.5 倍 | 25 倍 | 50 倍 |
| ×8 | 9.5 倍 | 32.5 倍 | 65 倍 |
| ×9 | 12 倍 | 42.5 倍 | 85 倍 |
| ×10 | 14.5 倍 | 52.5 倍 | 105 倍 |

画面には現在の成立数を含む 5 行を表示する。×6 以降も配当の増加幅が小さくならない式で継続し、×5 以降は 0.5 BET 刻みの値になる。単位を BET の 1/100 として、×1〜×5 の列は直線 `[20,50,150,250,400]`、三角 `[50,200,400,750,1250]`、ヘキサゴン `[100,400,800,1500,2500]`。`t = 成立数 - 5` に対し、×6 以降は `×5 の値 + (×5 − ×4) × t + 追加係数 × floor(t² / 4)`。追加係数は順に 50・250・500。

## 保存データ・継続との互換性

`CURRENT_REVISION = 280` と、まとまり処理の導入境界 `GROUPED_REVISION = 278` を分離した。保存済み revision 248 / 278 のゲームは、以前の配当・乱数・タイムラインで再開する。revision 278 の途中保存を読み込んでも単球処理には戻らない。配当表も再開したゲーム自身の revision に従う。

新 revision は役配当だけを変更する。同じ入力・乱数に対する初期盤面、補充、役成立数、消去数、色の進行、全消し発生、全消し原資の増分は従来通り。1 ドロップにつき BET の 5/100 を原資へ加える規則も維持する。

継続時は累計消去数と原資を保持し、次回 BET を変えても既存分を再計算しない。新しい消去分だけ新 BET で増える。途中中断では確定済みの持越しを保持し、その台自身が通常の 8 球を完了して WIN 0 になった場合に原資・消去合計・継続表示をリセットする。判定条件は従来通りだが、ごく小さい BET では役配当の切捨て結果が変わる可能性があるため、旧配当と新配当で常に同じ WIN 正負になるとは主張しない。

既存のファイル名 `sixdrop-ui-v278.*` と API 名 `SixDropUiV278` は参照互換性のため維持し、内部 UI version は 280 とした。v279 までの再生・配当演出修正を引き継ぐ。

`docs/qa-v278/sixdrop-payout-validation.json` の役成立数ヒストグラムを BET 100 で新配当に換算した。各設定 8,000 ゲーム、合計 32,000 ゲーム。新しい独立抽選を実施した結果ではなく、同じ標本の配当だけを比較している。新しい信頼区間は算出していない。

### v282での高額表示の仕上げ

初回v281の390px・BET 300,000検査では、1,006,234の数字が左へ6.35画面pxはみ出した。数字を固定幅へfitした後にflexが枠を縮めたのが原因だった。v282ではロゴ・WIN・継続の実寸から使える幅を計算し、数字枠と子の文字をflexで再縮小しない。0の表示枠にも26pxの最小幅を確保した。既存の境界・ロゴ間隔assertionは維持した。
