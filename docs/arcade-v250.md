## タブと小盤面

- v249で作った9ゲームのロゴを非選択タブにも使用する。既存のテーマ背景 → ロゴ → ライブ盤面の順に重ね、上の名称帯をなくして盤面を拡大する。選択中は従来の大きなロゴを表示する。
- シュガー獲得マークはWINの横へ移す。WINが0でも獲得済みのシュガーを表示できる。
- リーチは全候補を連続した右から左のスクロールにする。配当増加のないODDS UPだけの候補は小盤面には出さない。候補がなければ空欄にする。
- 高額・超高額リーチの新規発生、または格上げのときに、そのゲームの小タブ内で通知する。同じ予測の再描画・選択し直しでは繰り返さない。分類は当該ゲームの増加WIN÷BETの3倍・10倍を使用する。
- BET単位切替を9個の小盤面から取り出し、共通の1個へまとめる。ALL表示ではゲームカード脇の空き領域、少数ゲーム表示では操作欄へ配置する。個別の追加BET・1 BETボタンは大きくする。単位切替そのものではBETやCREDITを変えない。
- 非表示、BFCache復帰、動きを減らす設定を考慮する。演出から抽選やゲーム状態を変更しない。

## シックスドロップ

全消しリーチのSVG円に`fill="none"`を指定し、共通CSSの透明塗り指定にもcircleを含める。既定の黒い塗りが盤面を覆う問題を修正する。実行用bundleと対応するソースを一致させる。

v248までの4連結、幾何役、支持・転がり・補充、固定パレット、消去1個ごとの現在BET×0.05のプログレッシブ加算、全消し後の継続、シックスドロップ自身の終了WINによる持越し／リセットを維持する。サーバーの色判定も各ゲーム自身のBETを基準とし、本来の最高役だけを虹色にする。

## パーティカステラ

### 盤面と1ゲームの進行

1辺5の正六角形、61穴に拡大する。接続は4個の同心六角形と6本の放射線の和集合、84辺。初期生地19穴、番号25穴、注入力UP2穴、火力スイッチ2穴、シュガー1穴は全P/O設定で共通とする。

前半5球で生地を注ぐ。最初は接続グラフで周辺1マスまで。注入力UPの番号へ直接HITすると、**その球は現在の注入力で処理し、次の球から**周辺2マス、3マスへ進化する。2つのUPはそれぞれ1回だけ発動する。

生地が火力スイッチへ初めて入ったとき、火力が1段階上がる。初期1、上限3。既に作動したスイッチへ再度注いでも上がらない。後半3球では最終火力に対応する範囲を焼く。焼成範囲の六角距離という扱いを維持し、前半の番号位置を後半へ引き継ぐ。ODDS UPは廃止する。

シュガーは指定穴のカステラが焼けた場合に獲得する。生地を注いだだけでは獲得しない。画面ではその焼成演出の終了を待ち、1ゲームに1度だけ共通シュガーへ加算する。

### マークとゲージ

| 対象 | 表示 |
|---|---|
| 注入力UP | 青いしずく＋上向き矢印 |
| 火力スイッチ | オレンジの炎＋小さなスイッチ |
| シュガー | ピンクの結晶＋きらめき |
| 現在の注入力・火力 | それぞれ3段のゲージ |

番号付き穴ではマークを右下のバッジへ寄せ、数字と重ならないようにする。火力ゲージは生地がスイッチへ届く描画タイミングに合わせる。小盤面では背景を透明にし、主盤面の情報欄を省いて穴を大きく描く。

### 初期配置とP/O調整

通常12型と「大宴会」1型、計13型を用意した。初期生地と番号の置き場所は60度回転対称・鏡映対称。注入力UPと火力スイッチはそれぞれ対向する2穴に配置する。型と向きを開始時に選び、数字1〜25を番号穴へ重複なく配置する。以降の抽選結果を見て配置を変更しない。

型の選択比率を変更して50〜150%のP/O設定へ対応する。数字・初期生地・スイッチ位置の組み合わせで期待配当を変え、配当表や特殊穴の個数は共通に保つ。61穴全焼が実際に可能な「大宴会」の選択率は全設定で3%とする。この3%を含む期待配当から通常型の混合率を求める。

共通配当表は次の閾値式。例えば焼成14〜17個は0.2BET、18〜21個は0.4BETになる。

| 18以上 | 0.4 |

### 旧ラウンドとの互換

既存37穴のcheckpointは旧ルールを`PartyCastellaRules.legacy`として維持し、そのラウンドが終了するまで旧配当・旧シュガー条件で継続できる。新しく開始するゲームから61穴になる。8球目の焼成演出中に保存された状態を精算workerが復元した場合も、追加HITを待たず、未反映のシュガーと終了精算を一度だけ完了する。通常画面の焼成演出待機は維持する。描画は実際の穴数から半径を決める。hostは`payoutState(state)`と`payRowsFor(state)`で適切な配当を選ぶ。

## 検証と公開

ルール回帰は13型×12方向、720実ゲーム、41,040件の予測比較、checkpointのJSON復元、61全焼の実例、旧37穴の同一結果を対象とする。ブラウザー試験は隔離した実Nodeサーバーを起動し、共有抽選の正規APIから番号を送り、タブ・BET・リーチ・カステラの8球進行を確認する。

CIのブラウザー結果と公開検証は確定後にこの節とQA記録へ追記する。公開試験はAPI／WebSocketをブラウザー内で遮断して配信ファイルと初期化を確認し、公開サーバーへBET・抽選・精算を送らない。

## 更新方法

GitHub Pagesの反映と、Windowsで稼働しているサーバーのソース更新は別。Windowsは最新mainを反映し、`.runtime`・`.tools`・`data`を保持したうえで、既存の`start-shared-machine-tunnel.cmd`から再起動する。ホスト・管理画面・クライアントを再読み込みする。ランチャー起動だけではソース更新にならない。Windows実機、iPhone実機、スピーカー聴感は今回の自動試験には含まない。
